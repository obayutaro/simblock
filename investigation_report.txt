【1-1】recordTrafficSend/recordTrafficRecvの実装確認
----------------------------------------------------------------------------------------------------------------------------------
実装:
  - recordTrafficSend: 送信トラフィック量を記録
  - recordTrafficRecv: 受信トラフィック量を記録
  - 両方とも trafficPerSecond.put(second, trafficPerSecond.getOrDefault(second, 0L) + sizeBytes)
  - 秒単位で集計: second = timestampMs / 1000

【1-2】printTrafficBandwidthStatsの計算ロジック確認
----------------------------------------------------------------------------------------------------------------------------------
計算方法:
  - 各秒ごとのトラフィック量（バイト）をビットに変換: bps = bytesPerSecond * 8
  - 最大値: maxBps = max(bps)
  - 最小値: minBps = min(bps)
  - 平均値: avgBps = totalBps / count

⚠️ 潜在的な問題:
  1. 平均値の計算: totalBps / count は各秒のbpsの平均
     → これは「秒間平均トラフィック量」ではなく「各秒のトラフィック量の平均」
  2. 秒単位の集計: 同じ秒内のすべてのトラフィックが合計される
     → これは正しい

【1-3】shareContext/receiveSharedContextでの呼び出し確認
----------------------------------------------------------------------------------------------------------------------------------
shareContext:
  - 各targetNodeに対して recordTrafficSend(blockSize, currentTime) を呼び出し
  - blockSize = BLOCK_SIZE = 120KB
  - currentTime = getCurrentTime() (シミュレーション時間、ミリ秒)

receiveSharedContext:
  - 受信成功時に recordTrafficRecv(blockSize, currentTime) を呼び出し
  - blockSize = BLOCK_SIZE = 120KB
  - currentTime = getCurrentTime() (シミュレーション時間、ミリ秒)

⚠️ 潜在的な問題:
  1. 送信と受信の両方が記録されている
     → 実際のネットワーク負荷は約2倍になる可能性がある
  2. targetNodesが空の場合でも recordTrafficSend が呼ばれる
     → これは意図的な実装（ブロードキャスト試行を記録）

【2-3】タイムスタンプの計算確認
----------------------------------------------------------------------------------------------------------------------------------
getCurrentTime()の実装:
  - Timer.getCurrentTime() はシミュレーション時間（ミリ秒）を返す
  - 秒単位への変換: second = timestampMs / 1000

⚠️ 潜在的な問題:
  1. シミュレーション終了時点でのトラフィックのみが記録される
     → シミュレーション中に発生したすべてのトラフィックは記録されている
  2. 秒単位の集計: 同じ秒内のすべてのトラフィックが合計される
     → これは正しい
  3. 平均値の計算: 各秒のトラフィック量の平均
     → これは「秒間平均トラフィック量」として正しい
