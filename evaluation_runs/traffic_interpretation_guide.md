# トラフィック量の解釈ガイド

## 概要

`detailed_comparison_table.md`のトラフィックデータを実際のネットワークトラフィック量として参考にする場合の解釈方法を説明します。

## トラフィック量の種類

### 1. 送信平均（Send Average）

**定義**: 送信側から見たトラフィック量の平均値

**記録方法**:
- `recordTrafficSend()`が呼ばれるたびに記録
- 各送信イベントごとに`BLOCK_SIZE`（120KB）が記録される

**意味**:
- **実際に送信されたデータ量**を表す
- ネットワーク上を流れたデータ量の送信側からの視点

### 2. 受信平均（Receive Average）

**定義**: 受信側から見たトラフィック量の平均値

**記録方法**:
- `recordTrafficRecv()`が呼ばれるたびに記録
- 各受信イベントごとに`BLOCK_SIZE`（120KB）が記録される

**意味**:
- **実際に受信されたデータ量**を表す
- ネットワーク上を流れたデータ量の受信側からの視点

### 3. 合計平均（Total Average）

**定義**: 送信平均 + 受信平均

**計算方法**:
```
合計平均 = 送信平均 + 受信平均
```

**意味**:
- **ネットワーク全体の負荷**を表す
- 送信側と受信側の両方の負荷を含む

## 実際のネットワークトラフィック量として参考にする場合

### ケース1: 実際に転送されたデータ量を知りたい場合

**推奨**: **送信平均**または**受信平均**のどちらか一方を見る

**理由**:
- 1つのデータ転送イベントは、送信側と受信側の両方で記録される
- 実際に転送されたデータ量は、送信側から見ても受信側から見ても同じ
- ただし、ブロードキャストの場合、1つの送信が複数の受信を生むため、受信平均の方が大きくなる可能性がある

**例**:
```
P10_10_ON (NEIGHBORS_ONLY):
- 送信平均: 112,718,360 bps
- 受信平均: 6,695,738 bps
- 合計平均: 118,069,037 bps

実際に転送されたデータ量: 約112.7 Mbps（送信平均を参考）
```

### ケース2: ネットワーク全体の負荷を知りたい場合

**推奨**: **合計平均**を見る

**理由**:
- ネットワーク全体の負荷は、送信側と受信側の両方の負荷を含む
- 実際のネットワークインフラの負荷を評価する場合に適している

**例**:
```
P10_10_ON (NEIGHBORS_ONLY):
- 送信平均: 112,718,360 bps
- 受信平均: 6,695,738 bps
- 合計平均: 118,069,037 bps

ネットワーク全体の負荷: 約118.1 Mbps（合計平均を参考）
```

## 送信平均と受信平均が異なる理由

### 1. ブロードキャストの特性

- **1つの送信**が**複数の受信**を生む
- 例: 1つのノードが10個のノードにブロードキャストする場合
  - 送信: 1回 × 120KB = 120KB
  - 受信: 10回 × 120KB = 1,200KB
  - 実際に転送されたデータ量: 1,200KB（受信側の方が大きい）

### 2. ノード数の違い

- 送信側のノード数と受信側のノード数が異なる
- 例: 10個のノードが100個のノードに送信する場合
  - 送信側: 10個のノード
  - 受信側: 100個のノード
  - 受信平均の方が大きくなる傾向がある

### 3. 非対称な通信パターン

- REQUEST_BASEDモードでは、要求と応答が非対称になる可能性がある
- 例: 要求は小さいが、応答は大きい場合

## 推奨される解釈方法

### 実際のネットワークトラフィック量として参考にする場合

1. **実際に転送されたデータ量**を知りたい場合:
   - **送信平均**を参考にする
   - または、**受信平均**を参考にする（ブロードキャストの場合は受信平均の方が正確）

2. **ネットワーク全体の負荷**を知りたい場合:
   - **合計平均**を参考にする
   - これはネットワークインフラの負荷を評価する場合に適している

3. **比較評価**を行う場合:
   - 同じ指標（送信平均、受信平均、または合計平均）で比較する
   - `detailed_comparison_table.md`では**合計平均**で削減率を計算している

## 具体例

### P10_10_ON (NEIGHBORS_ONLY)

```
送信平均: 112,718,360 bps (約112.7 Mbps)
受信平均: 6,695,738 bps (約6.7 Mbps)
合計平均: 118,069,037 bps (約118.1 Mbps)
```

**解釈**:
- 実際に転送されたデータ量: 約112.7 Mbps（送信平均）
- ネットワーク全体の負荷: 約118.1 Mbps（合計平均）
- 送信平均が受信平均より大きい理由: ブロードキャストにより、1つの送信が複数の受信を生んでいる可能性がある

### P10_10_ON (REQUEST_BASED)

```
送信平均: 4,352,479 bps (約4.4 Mbps)
受信平均: 3,983,501 bps (約4.0 Mbps)
合計平均: 8,249,448 bps (約8.2 Mbps)
```

**解釈**:
- 実際に転送されたデータ量: 約4.4 Mbps（送信平均）
- ネットワーク全体の負荷: 約8.2 Mbps（合計平均）
- 送信平均と受信平均が近い理由: REQUEST_BASEDモードでは、1対1の通信が多いため

## 結論

**実際のネットワークトラフィック量として参考にする場合**:

1. **実際に転送されたデータ量**を知りたい場合:
   - **送信平均**を参考にする（推奨）
   - または、**受信平均**を参考にする（ブロードキャストの場合は受信平均の方が正確）

2. **ネットワーク全体の負荷**を知りたい場合:
   - **合計平均**を参考にする（推奨）

3. **比較評価**を行う場合:
   - **合計平均**で比較する（`detailed_comparison_table.md`の削減率は合計平均で計算されている）
