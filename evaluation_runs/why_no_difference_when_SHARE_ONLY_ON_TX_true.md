# なぜブロック受信時の共有が抑止されると結果が変わらないのか

## 問題の整理

`FORERUNNER_SHARE_ONLY_ON_TX=true`の場合、REQUEST_BASEDモードとNEIGHBORS_ONLYモードの伝播時間が完全に同等（0.00%）になる理由を説明します。

## 重要なポイント

### 1. 未来コンテキスト共有のタイミング

未来コンテキスト共有は、`onTransactionPoolUpdate()`メソッドが呼ばれたときに実行されます。

**呼び出しタイミング**:
1. **トランザクション受信時** (`recvTxMessage()`)
   - 個別のトランザクションが受信されたとき
   - `onTransactionPoolUpdate(newTransactions)` が呼ばれる
   - `newTransactions`には1つのトランザクションが含まれる

2. **ブロック受信時** (`recvBlockMessage()`)
   - ブロックが受信されたとき（`FORERUNNER_SHARE_ONLY_ON_TX=false`の場合のみ）
   - `onTransactionPoolUpdate(msg.getBlock().getTxList())` が呼ばれる
   - `msg.getBlock().getTxList()`にはブロックに含まれるすべてのトランザクションが含まれる

### 2. REQUEST_BASEDモードとNEIGHBORS_ONLYモードの違い

#### REQUEST_BASEDモード

**高速ノードの動作**:
1. `onTransactionPoolUpdate()`が呼ばれる
2. 未来コンテキストを生成
3. `shareContext()`が呼ばれる
4. `shareContextToRequestingNodes()`で、**要求してきたノードにのみ送信**

**低速ノードの動作**:
1. `onTransactionPoolUpdate()`が呼ばれる
2. `requestFutureContext()`で要求を送信
3. 要求を受けたノードから未来コンテキストを受信

#### NEIGHBORS_ONLYモード

**高速ノードの動作**:
1. `onTransactionPoolUpdate()`が呼ばれる
2. 未来コンテキストを生成
3. `shareContext()`が呼ばれる
4. `getTargetNodesForBroadcast()`で、**隣接ノードすべてにブロードキャスト**

**低速ノードの動作**:
1. `onTransactionPoolUpdate()`が呼ばれる
2. `startWaitingForSharedContext()`で待機
3. 隣接ノードからブロードキャストされた未来コンテキストを受信

### 3. ブロック受信時の共有が抑止されるとどうなるか

#### FORERUNNER_SHARE_ONLY_ON_TX = false の場合

**動作フロー**:
1. **トランザクション受信時**:
   - 個別のトランザクションが受信される
   - `onTransactionPoolUpdate()`が呼ばれる
   - 未来コンテキストが生成・共有される

2. **ブロック受信時**:
   - ブロックが受信される
   - ブロックに含まれるすべてのトランザクションが一度に処理される
   - `onTransactionPoolUpdate(msg.getBlock().getTxList())`が呼ばれる
   - 未来コンテキストが生成・共有される

**REQUEST_BASEDとNEIGHBORS_ONLYの違い**:
- **REQUEST_BASED**: 要求してきたノードにのみ送信（効率的）
- **NEIGHBORS_ONLY**: 隣接ノードすべてにブロードキャスト（非効率的）

**結果**: トラフィックに大きな差が生じる

#### FORERUNNER_SHARE_ONLY_ON_TX = true の場合

**動作フロー**:
1. **トランザクション受信時**:
   - 個別のトランザクションが受信される
   - `onTransactionPoolUpdate()`が呼ばれる
   - 未来コンテキストが生成・共有される

2. **ブロック受信時**:
   - ブロックが受信される
   - **`onTransactionPoolUpdate()`が呼ばれない**（抑止される）
   - 未来コンテキストの生成・共有が行われない

**REQUEST_BASEDとNEIGHBORS_ONLYの違い**:
- トランザクション受信時のみ共有が実行される
- しかし、**トランザクション受信時には、両モードの動作が実質的に同じになる**

## なぜ結果が変わらないのか

### 理由1: トランザクション受信時の動作が限定的

**トランザクション受信時の特徴**:
- 1つのトランザクションが個別に受信される
- トランザクションは順次処理される
- 未来コンテキストの生成・共有も個別に行われる

**REQUEST_BASEDモード**:
- 低速ノードが要求を送信
- 高速ノードが要求元にのみ送信
- しかし、トランザクション受信時には、要求のタイミングと未来コンテキスト生成のタイミングがずれる可能性がある

**NEIGHBORS_ONLYモード**:
- 高速ノードが隣接ノードすべてにブロードキャスト
- 低速ノードが待機して受信
- トランザクション受信時には、ブロードキャストのタイミングと受信のタイミングがずれる可能性がある

**結果**: トランザクション受信時のみでは、両モードの違いが伝播時間に現れにくい

### 理由2: ブロック受信時の共有が抑止される

**ブロック受信時の特徴**:
- ブロックに含まれるすべてのトランザクションが一度に処理される
- 未来コンテキストの生成・共有が一括で行われる
- **この時点で、REQUEST_BASEDとNEIGHBORS_ONLYの違いが最も明確に現れる**

**FORERUNNER_SHARE_ONLY_ON_TX = false の場合**:
- ブロック受信時に`onTransactionPoolUpdate()`が呼ばれる
- REQUEST_BASED: 要求してきたノードにのみ送信（効率的）
- NEIGHBORS_ONLY: 隣接ノードすべてにブロードキャスト（非効率的）
- **トラフィックに大きな差が生じる**

**FORERUNNER_SHARE_ONLY_ON_TX = true の場合**:
- ブロック受信時に`onTransactionPoolUpdate()`が呼ばれない
- 両モードの違いが現れる機会が失われる
- **結果が同じになる**

### 理由3: 伝播時間への影響が限定的

**伝播時間への影響**:
- 未来コンテキスト共有は、ブロック伝播時間に直接影響を与える
- しかし、トランザクション受信時のみの共有では、影響が限定的

**ブロック受信時の共有の重要性**:
- ブロック受信時に含まれるトランザクションリストを基に未来コンテキストを生成
- ブロック伝播と同時に未来コンテキストが共有される
- **この時点で、REQUEST_BASEDとNEIGHBORS_ONLYの違いが伝播時間に現れる**

**ブロック受信時の共有が抑止されると**:
- ブロック伝播と同時に未来コンテキストが共有されない
- トランザクション受信時のみの共有では、伝播時間への影響が限定的
- **結果が同じになる**

## 具体的な動作の違い

### シナリオ: ブロックに100個のトランザクションが含まれる場合

#### FORERUNNER_SHARE_ONLY_ON_TX = false

**動作**:
1. トランザクション受信時: 100回の`onTransactionPoolUpdate()`が呼ばれる
2. ブロック受信時: 1回の`onTransactionPoolUpdate()`が呼ばれる（100個のトランザクションが一度に処理される）

**REQUEST_BASEDモード**:
- ブロック受信時に、要求してきたノードにのみ送信
- トラフィックが削減される

**NEIGHBORS_ONLYモード**:
- ブロック受信時に、隣接ノードすべてにブロードキャスト
- トラフィックが増加する

**結果**: トラフィックに大きな差が生じる

#### FORERUNNER_SHARE_ONLY_ON_TX = true

**動作**:
1. トランザクション受信時: 100回の`onTransactionPoolUpdate()`が呼ばれる
2. ブロック受信時: `onTransactionPoolUpdate()`が呼ばれない（抑止される）

**REQUEST_BASEDモード**:
- トランザクション受信時のみ共有が実行される
- しかし、個別のトランザクションごとに処理されるため、効率が悪い

**NEIGHBORS_ONLYモード**:
- トランザクション受信時のみ共有が実行される
- しかし、個別のトランザクションごとに処理されるため、効率が悪い

**結果**: 両モードの動作が実質的に同じになり、結果が同じになる

## 結論

**なぜブロック受信時の共有が抑止されると結果が変わらないのか**:

1. **ブロック受信時の共有が、REQUEST_BASEDとNEIGHBORS_ONLYの違いを最も明確に示すタイミング**
   - ブロックに含まれるすべてのトランザクションが一度に処理される
   - REQUEST_BASED: 要求してきたノードにのみ送信（効率的）
   - NEIGHBORS_ONLY: 隣接ノードすべてにブロードキャスト（非効率的）

2. **トランザクション受信時のみの共有では、両モードの違いが現れにくい**
   - 個別のトランザクションごとに処理される
   - 要求のタイミングと未来コンテキスト生成のタイミングがずれる
   - 伝播時間への影響が限定的

3. **ブロック受信時の共有が抑止されると、両モードの違いが現れる機会が失われる**
   - ブロック伝播と同時に未来コンテキストが共有されない
   - トランザクション受信時のみの共有では、影響が限定的
   - 結果が同じになる

**まとめ**:
- `FORERUNNER_SHARE_ONLY_ON_TX=false`: ブロック受信時にも共有が実行されるため、REQUEST_BASEDとNEIGHBORS_ONLYの違いが明確に現れる
- `FORERUNNER_SHARE_ONLY_ON_TX=true`: ブロック受信時の共有が抑止されるため、両モードの違いが現れる機会が失われ、結果が同じになる
